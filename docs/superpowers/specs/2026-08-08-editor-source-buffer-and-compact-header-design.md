# 编辑器源 Markdown 缓存与紧凑头部设计

## 背景

当前笔记编辑器把已渲染的 `contenteditable` DOM 重新序列化为 Markdown。文本节点中的反斜杠会再次参与转义，导致笔记保存后出现额外的 `\\`，改变用户看到的真实内容。编辑器头部同时占用独立描述、标题输入、文件夹选择和操作栏，长文档中信息密度偏低。

## 目标

1. 保存和再次编辑笔记时保持 Markdown 源内容稳定，不重复增加反斜杠。
2. 不改变现有加密存储：仍使用同一 Markdown 字符串进入现有 `enc:v1` 加密流程，不增加数据库字段、不改变 API 或附件协议。
3. 压缩编辑器头部：标题成为头部主标题，文件夹选择与取消/保存同处操作栏，移除图片提示文案。
4. 保留正文粘贴图片、编辑区域拖拽图片、附件加密、失败恢复和重试行为。

## 非目标

- 不引入富文本编辑器或运行时依赖。
- 不改变 Markdown 存储格式、PBKDF2、AES-GCM、认证 Cookie、D1 schema 或附件加密协议。
- 不把 HTML 保存到数据库。

## 设计

### 1. 双层编辑模型

编辑器会话增加源 Markdown 缓存：

- 打开笔记时，解密后的 Markdown 同时作为 `editorSourceMarkdown` 和渲染输入。
- 编辑器未发生修改时，保存直接使用 `editorSourceMarkdown`，避免无变化保存重新序列化。
- 用户输入、工具栏命令、图片插入或附件 token 变更后，标记源缓存为 dirty，并通过现有序列化器生成一次新的 Markdown 源。
- 保存前仅对当前源 Markdown 做附件 token 替换和加密；保存成功后用最终 Markdown 重置源缓存和 dirty 基线。
- 保存失败时保留源缓存、DOM 和附件草稿，重试继续使用同一源内容。

源缓存只存在当前页面编辑状态，不写入 localStorage，不新增数据库列；数据库仍只接收加密后的 Markdown。

### 2. 反斜杠保真

文本节点序列化不再无条件转义已有反斜杠。仍保留对 Markdown 控制字符的必要转义，代码节点继续只处理代码围栏冲突。新增回归测试覆盖：

- `pmr\\_01@126.com` 保存后不变；
- 含粗体、列表、代码块的文本仍能往返；
- 未修改的原始 Markdown 保存不触发重新序列化。

### 3. 紧凑编辑器头部

- `editorTitle` 移入 `.modal-head`，作为可编辑的视觉主标题；保留 `modalTitle` 作为无障碍/状态标题。
- 删除头部描述“记录会在此设备加密后保存，正文支持在线文档式编辑”。
- `editorFolder` 选择器移动到 `composerActionBar`，与取消、保存按钮同一操作区；桌面端横向排列，窄屏自动换行。
- 删除附件拖放提示的可视区域和提示文案。正文编辑区与编辑卡继续接收 `paste`、`dragover`、`drop`，图片仍按原附件加密流程处理；附件状态信息仍保留用于反馈。
- 保存/取消操作栏继续 sticky，标题和文件夹操作不随正文长度消失。

## 数据流

```text
解密 Markdown
  -> editorSourceMarkdown
  -> renderMarkdown(contenteditable)
  -> 用户编辑/工具栏/图片事件
  -> 一次性 serializeEditorMarkdown
  -> 附件 token 替换
  -> buildNoteSaveContent
  -> 现有 enc:v1 加密
  -> API 保存
```

## 错误处理

- 源缓存为空且正文、标题均为空时继续使用现有校验。
- 序列化或附件上传失败时不清除源缓存、DOM 或草稿。
- 保存成功后才重置 dirty 基线；刷新失败仍沿用已有恢复逻辑。

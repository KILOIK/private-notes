# 编辑器可靠性与文件夹二级分类优化设计

## 背景

当前在线文档编辑器已经支持受控 `contenteditable` 和加密 Markdown 保存，但真实浏览器生成的编辑 DOM 与测试中的理想 DOM 不完全一致，导致有序列表、代码块等语义在保存时被降为纯文本。内联编辑保存后，保存状态还可能残留在旧容器上，使后续编辑区域无法点击。

本次优化继续基于用户提供的三张问题截图和四项需求：

1. 编辑页的“取消 / 保存”固定在顶部悬浮操作栏，长文档中始终可用。
2. Markdown 生成的数字列表、代码块等结构保存后仍能正确阅读和再次编辑。
3. 保存成功、失败和取消后都必须解除锁定，不留下页面不可操作状态。
4. 移除全局“全部 / 笔记 / 密码”分类栏，将“笔记 / 密码”作为当前文件夹下的二级分类。

## 目标

- 在不改变客户端加密、服务端密文格式、附件加密和现有分享安全边界的前提下，修复编辑器的语义往返和保存状态问题。
- 让编辑操作在长文档、内联编辑和移动视口下保持可达。
- 让文件夹成为唯一的一级导航，上下文明确地显示当前文件夹中的笔记与密码数量。
- 通过失败测试覆盖浏览器真实 DOM 包装、保存状态清理和层级导航模型，防止回归。

## 非目标与约束

- 不修改 PBKDF2、AES-GCM、`enc:v1`、Vault 隔离、认证 Cookie、锁定/重新验证、Authenticator、D1/R2 密文和阅后即焚分享流程。
- 普通笔记仍保存加密 Markdown，不在服务端保存富文本 HTML。
- 不引入第三方富文本编辑器或新的运行时依赖。
- 不允许未知 HTML、危险 URL、未知图片来源进入可执行 DOM 或 Markdown 输出。
- 密码秘密字段不进入列表摘要、整条复制和分享流程。
- 保留 `activeFolderId` 与 `activeCategory` 作为内部筛选状态，改变的是导航呈现和状态默认值。

## 交互设计

### 顶部悬浮编辑操作栏

编辑卡片顶部在标题区下方增加 `.composer-action-bar`：

- 左侧显示编辑状态：默认无文案，保存中显示“保存中…”，失败显示可读错误。
- 右侧固定两个按钮：“取消”和“保存”。
- 工具栏位于操作栏之后，并继续横向滚动；正文标题、文件夹、附件提示和编辑画布位于其下方。
- 操作栏和工具栏在编辑卡片内部 `position: sticky`，不会造成页面级横向滚动。
- 保存中禁用取消和保存，编辑容器设置 `inert` 与 `aria-busy`；保存结束或失败时解除同一容器的锁定。

取消行为使用打开编辑器时的快照比较：标题、文件夹、记录类型、密码字段和序列化后的 Markdown 都参与比较。无变化直接关闭；有变化先确认“放弃未保存内容”。

### 文件夹树导航

移除 `categoryNav` 的“全部 / 笔记 / 密码”三个一级按钮。`folderNav` 成为唯一一级导航，每个文件夹行包含：图标、名称、总数量和展开指示。

当前文件夹展开时，在父项下渲染两个二级按钮：

- “笔记”与数量。
- “密码”与数量。

点击父项表示当前文件夹全部记录；点击二级项表示当前文件夹中对应类型。仅当前文件夹展开，首次解锁默认选择“未分类”。未分类仍是固定的第一个文件夹项；自定义文件夹按现有顺序追加。

文件夹模型为每个文件夹提供总数、笔记数、密码数和当前展开状态。现有筛选函数继续接收 `activeFolderId` 与 `activeCategory`，因此列表、阅读器、搜索和删除流程无需改变数据协议。

## 架构与数据流

### 编辑器块级序列化

`public/document-editor.js` 增加递归块级遍历：

- `DIV`、`SECTION` 等透明包装节点先检查是否包含块级子节点；有则逐个序列化子块，无则按段落处理。
- `H1`–`H6` 输出对应数量的 `#`。
- `P` 输出安全行内 Markdown。
- `UL/OL` 遍历 `LI`，输出 `-` 或递增数字标记；嵌套列表按层级保留缩进。
- `PRE` 读取自身或子级 `CODE` 文本，输出 fenced code block，并保留安全的 `language-*` 类名。
- `BLOCKQUOTE` 按行添加 `>`。
- `IMG` 只接受 `data-markdown-src` 中的 `attachment://` 或 `pending://` 引用。
- `A` 只接受 `http:` 和 `https:`；危险链接只保留文字。
- 未知节点只递归安全文本，不输出原始 HTML。

加载仍由 `renderMarkdown()` 生成白名单 DOM；保存始终经过 `serializeEditorMarkdown()`，再执行 pending 图片 token 替换，最后进入现有 `buildNoteSaveContent()` 和加密流程。

### 保存事务状态

保存开始时捕获实际宿主元素：弹窗编辑使用 `editorModal`，内联编辑使用 `readerEditor`。`setComposerSaving()` 或其包装函数接收这个明确的宿主引用，而不是在 `finally` 中根据已改变的 `editingInline` 状态重新推断。

保存流程保持以下顺序：

1. 捕获宿主并进入 saving 状态。
2. 等待所有附件上传 Promise；检查失败附件。
3. 序列化 Markdown，替换 pending token。
4. 校验 Vault 解锁状态、标题/正文和附件引用。
5. 加密标题和内容并提交 API 请求。
6. 关闭编辑器、刷新列表、需要时重开阅读器。
7. 在 `finally` 中对最初捕获的宿主解除 `inert` 和 `aria-busy`。

任何异常都保留编辑 DOM、标题和附件草稿，显示错误状态并允许再次保存。不会通过清空编辑器来“恢复”卡死状态。

## 错误处理与安全

- 保存请求返回 401、409、503 或网络异常时沿用现有错误文案，并确保状态栏恢复可操作。
- 保存状态不改变加密密钥和服务端协议；失败不会写入半成品内容。
- 取消未保存图片时继续调用现有附件草稿清理逻辑；保存失败不清理草稿。
- 文件夹解锁清理仍清空解密后的文件夹名、笔记列表和当前筛选。
- 导航二级分类只由解密后的本地模型生成，不新增明文数据库字段。

## 代码边界

- `public/document-editor.js`：递归块级序列化、命令和编辑 DOM。
- `public/composer-saving.js`：保存状态宿主引用和可恢复锁定。
- `public/app.js`：顶部操作栏接入、快照比较、保存流程、文件夹树事件和默认筛选。
- `public/index.html`：移除全局分类栏，增加操作栏和文件夹二级分类容器。
- `public/styles.css`、`public/workspace.css`：sticky 操作栏、工具栏偏移、树状导航和移动响应式样式。
- `public/workspace-model.js`：文件夹总数/笔记数/密码数及展开模型。
- `test/document-editor.spec.ts`：包装节点、列表、代码块和安全链接回归。
- `test/composer-saving.spec.ts`：宿主引用在成功、失败和内联移动后的锁定清理。
- `test/workspace-model.spec.ts`、`test/index.spec.ts`：层级导航模型和静态结构。

## 验收标准

- 长文档滚动到任意位置时，“取消 / 保存”仍可见且触控目标不少于 44px。
- 点击取消不会误丢未保存内容；确认放弃后才退出。
- 现有包含数字列表、代码块、标题、引用、图片和链接的 Markdown，打开 → 保存 → 重开后结构不变。
- 内联编辑保存成功或失败后，编辑器和页面均可继续点击；不会残留 `inert`。
- 文件夹一级列表不再显示全局“全部 / 笔记 / 密码”；当前文件夹可展开“笔记 / 密码”并显示正确计数。
- 桌面、紧凑桌面和 390×844 移动视口无页面级横向滚动。
- `npm run check`、相关 Vitest 和工具测试全部通过。

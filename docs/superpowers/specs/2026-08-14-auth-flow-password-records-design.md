# Authenticator、密码展示与登录记录设计

## 背景

现有 Authenticator 页面要求用户在输入六位验证码后额外点击“验证并进入”。密码阅读器为每个字段显示文字复制按钮，secret 字段以“显示”文字控制可见性；移动端将标签、正文和操作纵向堆叠。设置页列出全部 `auth_sessions`，没有保留上限或翻页。

## 目标

完成一条完整旅程：用户完成 Authenticator 验证登录，能快速安全地复制密码记录字段，并在手机上紧凑阅读字段，同时能在设置页浏览受限且可翻页的登录记录。

## 范围

1. 用户输入或粘贴满六位 Authenticator 验证码后自动提交验证；验证进行中不得重复请求。
2. 密码阅读器中，点击字段内容即可复制原始字段值；不显示“复制”文字按钮。secret 字段使用有无障碍名称和 hover 标题的眼睛图标切换显示状态。
3. 手机视口（最大宽度 767px）中，密码字段采用左侧标签、右侧内容的紧凑网格。标签为较小字体，内容占据主宽度；内容可换行但不被压缩到页面外。
4. 每个 Vault 的 `auth_sessions` 只保留按登录时间排序的最近 100 条。创建新会话后删除更早记录；被删除记录的 Cookie 将不再通过 Session 校验。
5. `GET /api/auth/devices` 使用不透明游标按登录时间倒序返回 10 条记录及下一页游标。设置页提供上一页和下一页按钮，最多显示该 Vault 的 100 条保留记录。

## 非目标与兼容性

- 不修改 TOTP 算法、恢复码、密码加密、Cookie 格式、Vault 隔离或 Authenticator 启用流程。
- 不新增 migration、表或依赖。现有 `auth_sessions` 的 `(vault_id, login_at DESC)` 索引用于排序和保留清理。
- 现有未分页客户端可继续读取响应的 `devices` 字段；新增 `nextCursor` 为附加字段。
- 已有超过 100 条会话的 Vault 会在下一次成功登录时被裁剪；设备 API 本身也只查询最近 100 条，避免首次浏览泄漏历史规模。

## 交互与数据流

### Authenticator 自动验证

- 单字符输入、连续输入和粘贴都先规范化为数字。
- 当六个输入框全部包含数字，且当前没有验证请求时，调用已有 `verifyPendingTotp()`。
- 自动提交与手动按钮共用同一互斥状态；按钮和验证码输入在请求期间禁用。
- 失败时保留验证码和错误文案，重新启用输入；用户可更正并再次自动提交或点击按钮。

### 密码字段

- 字段正文渲染为语义 button，视觉上保持纯文本；点击或键盘激活调用现有 Clipboard API 复制真实值。
- secret 字段正文仍在隐藏时显示等长圆点，复制行为仍复制真实值。
- secret 的显示切换按钮不触发复制，使用 CSS 眼睛图标、`aria-label` 和 `title` 表达当前动作。

### 移动布局

- 密码阅读字段使用三列：固定且较窄的标签列、可收缩内容列、仅 secret 使用的操作列。
- 多行字段的内容可在右侧换行，标签保持左侧对齐；不恢复纵向堆叠布局。
- 内容复制按钮的最小触控目标维持 44px；字段正文的 button 保持可聚焦和可见 focus 状态。

### 登录记录保留与分页

- 创建 `auth_sessions` 后，在同一 Vault 范围内按 `login_at DESC, id DESC` 裁剪，只保留前 100 条。
- 设备 API 先限定最近 100 条，再依据游标查询下一页，并返回第 11 条存在时生成的 `nextCursor`。
- 客户端首次打开设置读取第一页；前进时保存当前游标，返回时从游标栈恢复上一页。请求失败时保留当前已显示列表并给出状态文案。

## 错误处理

- 无效、缺失或过期的设备分页游标返回 `400 invalid_cursor`，不执行模糊查询。
- Clipboard API 失败时使用现有状态消息提示，不把敏感值写入 DOM、日志或其他回退存储。
- TOTP API 失败沿用已有错误处理，并确保互斥状态在 `finally` 中恢复。

## 验收标准

1. 输入或粘贴第六位验证码后，在无需点击按钮的情况下发起一次验证请求；请求期间不会重复提交。
2. 密码记录没有“复制”文字按钮；点击任意有值字段正文复制其真实值，secret 的显示控制为眼睛图标。
3. 375px 手机视口中，密码标签和内容优先横向排列，内容列明显宽于标签列，长内容只在内容列换行。
4. 第 101 次成功登录后，数据库只保留该 Vault 最近 100 条 Session；设备 API 每页 10 条，并可在十页内前后翻页。
5. 相关 Worker、客户端单测、类型检查和关键浏览器路径通过。

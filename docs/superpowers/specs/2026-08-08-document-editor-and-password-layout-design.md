# 在线文档式笔记与密码记录版面优化设计

日期：2026-08-08
状态：已确认，待实施

## 背景与目标

本轮是在已经上线的经典三栏加密笔记工作区上继续优化，不是重做安全或数据架构。参考用户提供的五张截图，需要同时解决导航层级、普通笔记编辑体验、Markdown 阅读报错、密码字段可配置性和密码阅读版面五个问题。

最终目标是：左栏信息架构更符合文件夹心智；普通笔记像在线文档一样直接编辑；旧笔记中的常见 Markdown 能稳定打开；密码记录不再被固定字段束缚；密码阅读页优先展示内容，操作退到右侧低权重位置。

## 完整需求理解

### 1. “未分类”归入“我的文件夹”

- “未分类”不再与“全部 / 笔记 / 密码”并列放在资料库分类区。
- “我的文件夹”标题下，先显示“未分类”，再显示用户创建的文件夹。
- “未分类”仍表示 `folderId` 为空或原文件夹已不存在的记录，不创建真实文件夹记录，也不改变既有数据。
- “未分类”继续显示记录数量、支持选中筛选，并和普通文件夹使用统一的行高、图标、选中态和数量布局。
- “未分类”不提供重命名、删除等文件夹管理操作。

### 2. 普通笔记改为在线文档式编辑

- 普通笔记编辑从表单式标题输入框 + Markdown textarea，改成右侧正文区域内的文档画布。
- 标题是画布顶部的独立大标题输入区；正文是可直接排版的所见即所得编辑区。
- 工具栏固定在文档画布顶部，在正文滚动时保持可用；移动端允许横向滚动，不挤压正文。
- 基础工具包括：撤销、重做、正文/标题层级、粗体、斜体、下划线、删除线、引用、无序列表、有序列表、行内代码、代码块、链接和图片。
- 工具栏命令直接作用于当前选区；不可用命令显示禁用状态。
- 粘贴普通文本保留段落；粘贴或拖入图片继续沿用既有客户端加密附件流程。
- 编辑区提供清晰的空标题、空正文提示，但提示不进入保存内容。
- 保存和取消保留在编辑区可发现的位置；保存期间继续使用既有防重复提交和最新操作校验。

### 3. 保留加密 Markdown 作为存储格式

- 所见即所得只改变编辑层，不改变服务端或密文内容格式。
- 打开编辑器时，将现有 Markdown 转为受控的编辑 DOM。
- 保存时，将编辑 DOM 转回规范化 Markdown，再进入现有 `enc:v1` 加密和保存流程。
- 已有 Markdown 笔记必须继续可读、可编辑；无法映射的结构应尽量保留为文本或代码，而不是静默丢失。
- 支持的首批双向结构：段落、换行、H1–H3、粗体、斜体、下划线、删除线、引用、无序/有序列表、行内代码、代码块、链接、图片。
- 下划线没有通用 Markdown 语法，保存时使用现有渲染器可安全识别的有限 `<u>` 表达；其它编辑器生成的任意 HTML 不直接保存。
- 链接和图片 URL 继续经过协议校验；禁止脚本协议和不受支持的危险 URL。

### 4. 修复普通笔记默认打开报错

- 当前错误 `Cannot read properties of undefined (reading 'toLowerCase')` 来自 `public/markdown.js` 的内联 token 正则捕获组错位。
- 粗体、链接、行内代码等 token 被错误进入图片分支，图片 URL 捕获值为 `undefined`，随后调用 `toLowerCase()` 报错。
- 修复必须调整捕获分组或改成具名/明确分支，不用简单的可选链吞掉错误。
- 回归测试至少覆盖：粗体、斜体、删除线、Markdown 链接、行内代码、图片、安全 URL、危险 URL、混合内联格式。
- 阅读页遇到单个不支持的 token 时应降级显示该文本，不让整篇笔记空白。

### 5. 密码记录标题独立，所有正文默认字段可删除

- 密码记录标题改为编辑器顶部独立且固定的“记录标题”输入框，承担列表标题和阅读页标题职责。
- `名称`、`用户名`、`密码`、`网址`、`备注` 不再是强制存在的固定字段；它们和自定义字段一样都可以删除。
- 新建密码记录时仍可预置这五个常用字段，保持开箱可用，但用户可以按需要删到零个正文项。
- 字段删除是编辑草稿行为，保存前可通过“添加字段”重新添加文本、隐藏值或多行文本字段。
- 每个字段保留可编辑标签和值；隐藏值字段默认使用密码输入。
- 为兼容旧数据，解密旧记录后继续识别现有 `name / username / password / url / notes` ID，但归一化不再补齐被删除的字段。
- 旧记录若只有 `name` 字段承担标题，首次加载时用旧 `name` 值回填独立标题；保存后标题独立存储，正文中的 `name` 字段仍保留，除非用户删除。
- 保存校验只要求独立标题有效；正文允许没有字段或包含空值字段。

### 6. 密码阅读页突出字段正文

- 页面顶部只显示独立标题和低权重记录元信息，字段列表成为主要视觉内容。
- 每行使用“字段标签 / 字段正文 / 右侧操作”三列结构：标签固定为较弱颜色，正文占主要宽度，复制和显示/隐藏按钮靠右。
- 普通值直接显示；隐藏值默认用圆点遮挡；备注和其它多行内容自然展开并保留换行。
- 空字段不制造大块空白：默认隐藏无值字段；如果需要让用户知道字段存在，可在编辑页查看。
- 复制、显示/隐藏使用简约图标按钮，保留 `aria-label`、键盘焦点和至少 44px 的触控范围，但不显示大面积按钮背景。
- 长网址、恢复码、密钥等使用 `overflow-wrap: anywhere`，不能撑开右侧栏或产生页面级横向滚动。
- 阅读页不增加密码记录整体复制或分享；继续只允许逐字段复制。

## 方案比较与决策

### 方案 A：原生 `contenteditable` + 受控 Markdown 双向转换（采用）

优点：不引入大型第三方编辑器，包体和供应链风险低；能复用当前原生 ES modules、加密 Markdown、附件和保存流程；可以针对本产品支持的 Markdown 子集做严格过滤。
代价：需要自己维护选区、命令状态和 DOM 到 Markdown 的规范化转换；复杂嵌套格式首版只做受控子集。

### 方案 B：引入完整富文本编辑器框架

优点：编辑命令、选区、历史栈和插件生态更成熟。
代价：新增较大依赖和安全审计面，数据模型需要额外适配，超出当前原生前端结构；不利于控制加密 Markdown 的最小兼容边界。

### 方案 C：继续使用 textarea，仅模拟在线文档外观

优点：实现最小、保存完全不变。
代价：工具栏仍只会插入 Markdown 符号，不是真正的所见即所得，不满足已确认的编辑体验，因此不采用。

## 页面与交互设计

### 左栏

资料库分组保持“全部、笔记、密码”。其下是“我的文件夹”标题和新建文件夹按钮。分组中的第一项固定为“未分类”，之后按现有文件夹排序显示用户文件夹；最近删除仍固定在左栏底部。

### 普通笔记编辑状态

右栏从上到下分为：

1. 面包屑和低权重元信息；
2. 文档工具栏；
3. 居中但充分利用宽度的文档画布；
4. 独立大标题；
5. 正文编辑区；
6. 附件状态和保存/取消操作。

编辑器视觉沿用现有工作区的白色背景、深色正文、浅灰边界和绿色焦点色。它参考图二的在线文档密度和工具栏结构，但不复制图中 AI、表格等当前产品没有的数据能力。

### 密码编辑状态

顶部显示独立“记录标题”输入和文件夹选择。正文区域是字段卡片列表；每张卡片包含可编辑标签、值输入、必要的显示/隐藏，以及右上角低权重删除操作。底部提供三类添加按钮：文本字段、隐藏字段、多行字段。

### 密码阅读状态

字段列表不再采用大卡片和大输入框外观，而是轻分隔线的详情表。桌面端字段正文从约 35% 的水平位置开始，操作贴右；移动端改为标签在上、正文在下，操作仍靠右，不牺牲 44px 触控目标。

## 数据与兼容设计

- 普通笔记数据仍为 `{ version, type: 'note', folderId, markdown }`。
- 密码记录升级为仍可由现有加密 envelope 包裹的内容对象：`{ version, type: 'password', folderId, title, fields }`。
- 归一化逻辑兼容没有 `title` 的旧密码记录，并从旧 `name` 字段派生显示标题。
- 密码字段 ID 继续保持稳定；删除后不在归一化阶段重新生成。
- 不迁移 D1 明文列，不新增服务端可见标题或字段。
- 不改变 PBKDF2、AES-GCM、Vault 隔离、Authenticator、附件密文、分享和锁定模型。

## 模块边界

- `public/markdown.js`：修复内联渲染；提供安全的 Markdown ⇄ 编辑 DOM 转换纯函数。
- `public/document-editor.js`：管理编辑 DOM、选区命令、撤销/重做状态和规范化输出，不直接访问 API 或密钥。
- `public/index.html`：调整未分类位置、在线文档编辑结构、独立密码标题和字段操作结构。
- `public/app.js`：连接现有状态、加密保存、附件、打开/关闭编辑器和新标题模型。
- `public/password-fields.js`：允许删除任意字段并保留新增字段能力。
- `public/note-records.js`：兼容旧密码记录，停止强制补齐固定字段。
- `public/password-ui.js`：独立标题保存载荷、可删除字段编辑 DOM、正文优先阅读 DOM。
- `public/workspace.css`：文档工具栏、画布、编辑区和密码详情表的响应式视觉。

## 错误处理与安全

- Markdown 单一 token 解析失败时降级为文本；不得通过 `innerHTML` 注入未过滤的用户内容。
- DOM 转 Markdown 只遍历白名单节点和属性，未知节点只保留安全文本内容。
- 链接、图片和粘贴内容继续过滤危险协议。
- 图片仍在客户端加密后上传；取消编辑继续清理未保存附件草稿。
- 密码字段不进入列表摘要；阅读时只在当前已解锁 Vault 的内存和 DOM 中存在。
- 锁定、退出、切换 Vault 时继续清空标题、编辑 DOM、字段值和已显示秘密值。

## 测试与验收

### 自动化测试

- 导航：未分类位于我的文件夹分组，计数和筛选不变。
- Markdown：最小复现不再报错，所有内联格式和危险 URL 有回归覆盖。
- 编辑器：Markdown 转编辑 DOM、格式命令、编辑 DOM 转 Markdown、危险节点过滤、空文档和混合格式。
- 密码模型：默认字段可删除；旧记录兼容；不自动补回；独立标题保存；零字段有效。
- 密码 UI：每行正文优先、空值隐藏、秘密默认遮挡、逐字段复制和显示切换。
- 完整 Vitest、类型检查和现有工具测试全部通过。

### 浏览器验收

- 使用项目现有浏览器测试方式，在桌面宽屏、紧凑桌面和手机视口验证。
- 对照图一检查未分类层级；对照图二检查工具栏、标题和文档画布；用图三对应旧笔记内容确认打开无报错；对照图四检查所有默认字段可删除；对照图五检查正文宽度和右侧简约按钮。
- 验证键盘 Tab 顺序、焦点可见、工具栏横向滚动、长值换行和 44px 触控目标。
- 保存后重新打开普通笔记和密码记录，确认内容、格式、标题、字段删除和加密流程均保持正确。

## 非目标

- 不增加多人协作、评论、版本历史、AI 写作、表格或实时同步。
- 不支持任意 HTML 富文本或完整第三方编辑器格式。
- 不修改服务端明文数据边界、认证、TOTP、分享策略或附件格式。
- 不改变列表摘要对密码秘密值的保护规则。

## 完成标准

1. “未分类”在“我的文件夹”分组内且筛选、数量正确。
2. 普通笔记可在右栏以真正所见即所得方式编辑，保存后仍为兼容的加密 Markdown。
3. 包含粗体、链接、行内代码等内容的旧笔记打开不再触发 `toLowerCase` 错误。
4. 密码标题独立；五个默认正文项全部可删除且不会被归一化补回。
5. 密码阅读页以正文为主，复制和显示操作在右侧简约呈现。
6. 桌面、紧凑桌面和移动端均无布局溢出，键盘和触控操作可用。
7. 现有安全模型和全部回归测试保持通过。
